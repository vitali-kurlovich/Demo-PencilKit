 - Поэтапная закраска, когда шаг за шагом закрашиваются определённым цветом участки рисунка, начиная с крупных участков, заканчивая небольшими деталями
 - Поэтапное рисование контуров

 ## Режим совместного рисования

В режиме совместного рисования пользователь видит рядом со своим холстом холст другого пользлователя.

Для реализации данного режима можно использовать gRPC в режиме stream, что-бы передавать данные нарисованных примитивов для холста.
Кроме gRPC можно использовать WebRTC для P2P соединения, что-бы разгрузить сервер

Так же можно использовать WebRTC для шаринга части экрана, передовая видео-поток
 
 
 ## Редактор уроков 

Для создания уроков можно либо разработать набор утилит для конвертации графических файлов и использовать графические редакторы, либо делать поноценный редактр под iPad

У каждого решения свои минусы и плюсы:
 - При использовании графического редактора затраты на создание урока будут ниже, поскольку это уже проверенная знакомая среда, ориентированная на создание графического контента
 - При реализации редактора в iPad появится возможность дать пользователям создавать свои уроки, а значит можно бесплатно наполнить галлерею уроков

Скорее всего лучшее решение будет гибридный вариант (предподготовка во внешнем редакторе и окончательное редактирование на iPad )


# Нефункциональные требования

 ## Производительность
  Для использования стилуса предъявляются высокие требования по производительности, поскольку любое отставание рисуемой линии от наконечника стилуса вызывает высокий дискомфорт у пользователя. 
  При проектировании иерархии экрана следует избегать большого скопления UI-элементов в области рисования, особенно полупрозрачных, поскольку это будет приводит к высокой нагрузуке на CPU/GPU при компоузе интерфейса. Так же следует учитывать, что высокие требования к производительности накладываются именно в момент рисования, поэтому можно скрывать некоторые элементы UI или отключать тяжёлые эффекты (размытие, тени, стекло) на время косания пера экрана 

  Следует уделить внимание профилированию производительности, получению метрик, например с помощю [OSSignposter](https://developer.apple.com/documentation/os/ossignposter), и избегать оптимизаций без ориентации на метрики. Кроме того, следует иметь возможность получать метрики с устройств пользователя, что-бы быстро реагировать, если на устройствах пользователя появились проблемы с производительностью после выхода обновлений, это можно реализовать с помощью [MetricKit](https://developer.apple.com/documentation/metrickit)

  ## Расход места на SSD
  Следует обратить внимание на занимаемое место ресурсами, что-бы программа не попадала хотя-бы в десятку программ по использованию меств нв SSD, поскольку это может привести к отказу пользователя от использования программмы

  Для уменьшения занимаемого места на SSD можно сделать:
   - Оптимизировать по размеру файлы уроков
   - Загружать уроки динамически, по ходу использования программы и удаление рание пройденых, можно использовать [Background Assets](https://developer.apple.com/documentation/backgroundassets)

# Технические детали

## Урок

Урок состоит из следующих компонентов:
 - Метаданные: название урока, описание, мининатюра урока
 - Описание каждого из шагов урока включающие: название, детальное текстовое описание, графические данные, цвета

Данные урока представляют собой текстовые и графические данные. 

Желательно для текстовых данных реализовать поддержку разных локализаций.
Графические данные могут быть представлены в виде растрового либо векторного формата.

### Растровые форматы
Главным достоинством растрового формата является простота интеграции в приложение, поскольку на уровне операционной системы поддержвается как множество форматов, так и простая реализация программной отрисовки. Растровые изображения обладают поддержкой высокой детализации, но для данного приложения это не даёт никаких приемуществ.

### Векторные форматы
Векторееые форматы предствалены значительно меньшим разнообразием и плохой поддержкой со стороны операционной системы (для iOS поддерживается PDF и несколько внутренниих форматов, например Symbols. svg-формат преобразуется в растр при сборке приложения). Несмотря на ряд технических сложностей, векторный формат выглядит наиболее подходящим. Главное приемущество векторного формата это возможность реализовать параметрическую отрисовку (можно задать программно цвет и обводку у фигуры ) и независимость от разрешения изображения.

Пример данных для урока можно посмотреть в [Arts/Lesson Rabbit Decompose](https://github.com/vitali-kurlovich/Demo-PencilKit/tree/main/Arts/Lesson%20Rabbit%20Decompose). Даже без оптимизации все графические данные в zip-архиве занимают ~100k

Класс __Step__ содержит данные для конкретного шага урока:
 - *metadata* - текстовые данные для шага (название, описание)
 - *tool* - настройки инструмента (позволит реализовать автоматический выбор инструмента и настройки цвета рисования)
 - *shape* - данные фигуры либо кривой которую закрашивают либо обводят на данном шаге урока
 - Метод *estimate* - производится оценка нарисованного пользователем


Класс __Lesson__ содержит данные урока и обеспечивает перемещение по шагам:
 - *metadata* - текстовые данные урока (название, описание)
 - *steps* - шаги урока
 - *currentStep* - текущий шаг
 - *isFinish* - флаг последнего шага
 - *next, prev* - методы итерирования по шагам

## Cопоставлении цвета

При сопоставлении цвета, функция сравнения должна учитывать диапазон цвета, поскольку добиться 100% совпадения цвета может быть проблемой для пользователя. Скорее всего для реализации функции сопоставлении цвета нужно будет учитывать хроматическую и яркостную составляющую. Для этого можно использовать Lab-color space. 

При сравнениии цвет представлять в виде 3d-вектора (L,a,b) и использовать скалярное произведение с вектором из целевого цвета. В результате получится величина равная произведению длин векторов на косинус угла между ними. Чем меньше угол между векторами, тем ближе к произведентю длинн векторов. Из соотношения  скалярного произведения векторов и скалярное произведения вектора цвета на самого себя можно дать оценку насколько цвет соответствует целевому 1 - соответствует полностью, -1 - противоположный цвет



## Рисование линий
Для того, что-бы определить насколько точно пользователь нарисовал линию можно использовать [Расстояние Фреше](https://en.wikipedia.org/wiki/Fr%C3%A9chet_distance), данная метрика определяет меру сходства кривых. Для каждого шага урока можно выставить пороговое значение данной метрики, что-бы выяснить нужно ли повторить ещё раз данный шаг урока.

Релизацию вычисления можно посмотреть тут: [FrechetDistance.swift](https://github.com/vitali-kurlovich/swift-mathkit/blob/main/Sources/MathKit/Measurment/FrechetDistance/FrechetDistance.swift)


## Формат файлов урока

Формат должен предоставлять метаданные, хранить графическую состовляющую и желательно поддерживать версионность
Урок можно хранить в виде папки с несколькими файлами, например:

+ [ Rabbit ]

  - metadata.json.zip

  - lesson.json.zip

  - thumb.svg.zip

Хранение в нескольких файлах позволит загружать уроки по частям (это может быть полезно для реализации галлереи уроков на сервере, когда нужно только название и thumbnail )

Формат может быть как человекочитаемым (json - например), так и бинарным.
У каждого формата могут быть свои достоинства и недостатки:

### Формат Json 
 Удобен для отладки, его легко читать и править
 Из недостатков: json даёт возможность легко иследовать и скопировать данные урока, а поскольку создание файлов уроков одна из самых затратных по времени задач, это может быть использовано для воровства данных потенциальными конкурентами

### Формат Protobuf
 Компактный бинарный формат, без схемы данных труден в отладке. Поскольку бинарный формат труден для анализа, использование его может дать дополнительный уровень защиты от копирования.

На практике лучше использовать гибрид:
  - При создании уроков использовать json-формат, при публикации конвертироваит json в бинарный формат.
